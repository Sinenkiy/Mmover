## 1. Архитектура, движение и lifecycle

Вынесена логика из MainActivity без внедрения нового общего архитектурного фреймворка:

| Компонент эталона | Ответственность |
| --- | --- |
| MotionController | Чистый Kotlin: Stopped, Moving, Waiting; смена фаз и отсчёт времени |
| TaskScheduler / MainThreadScheduler | Подставляемые часы и планировщик; Android-реализация через Handler |
| MovingBackgroundView | Загрузка/генерация текстуры, отрисовка, кадровое движение, освобождение |
| MovementDirection | Направление, расстояние до поворота, ограничение полос двумя направлениями |
| RewardAccess / RewardSession | Календарное право доступа, защита от повторной выдачи награды |
| RewardAccessController / PreferenceRewardAccessStore | Lifecycle проверки доступа и сохранение |
| MainAdsController и вспомогательные политики | Рекламные SDK, запросы, баннеры, rewarded, освобождение |
| MainActivity | Действия пользователя, отображение состояния, яркость/вибрация, передача lifecycle |

Обязательное поведение:

- Один ожидающий callback движения, отмена и защита от устаревших вызовов. Повторный старт не создаёт параллельные циклы.
- Остаток ожидания рассчитывается по монотонному deadline, а не количеством сработавших секундных тиков. Нулевая пауза корректна; в stealth используется случайная пауза в установленном диапазоне.
- `pause_duration` эталона хранит шаги по 5 секунд, не секунды. Настройки считываются перед очередной фазой.
- В фазе Waiting фон останавливается, экран затемняется, в центре отображаются режим и таймер. Не потерять это при переносе нового UI.
- `onPause` останавливает движение и вибрацию. После возврата самозапуска нет. `onDestroy` закрывает контроллеры, удаляет listeners/таймеры, очищает KEEP_SCREEN_ON.
- View Binding для UI; не удерживать Activity/View в переживающей экран ViewModel. UI-контроллеры и scheduler работают на главном потоке.
- Генерация и декодирование вне UI-потока. Отмена корутин не поглощается; attachment и номер запроса защищают от позднего результата. При detach отменить работу и освободить bitmap/shader.
- Движение через Choreographer работает при системном animator_duration_scale как 0, так и 1. Ограничение шага после зависшего кадра предотвращает резкий скачок.

### Случайное направление — последняя правка

Направление меняется каждые 2000 px пройденного пути, до циклического переноса координат текстуры. При 500 px/с это около 4 секунд движения, при 1000 — 2, при 200 — 10. Во время остановки путь не растёт; задержки кадров могут увеличить реальное время.

Штрихкод чередует вверх/вниз; остальные фоны получают случайный поворот на 45–315° относительно предыдущего направления. Вектор нормирован: скорость не зависит от угла. Кадр разбивается на границе 2000 px. На новом старте счётчик сбрасывается и выбирается начальное направление. Дополнительных таймеров и новых текстур при поворотах нет.

## 2. Навигация и запуск

- SettingsActivity создаёт SettingsFragment только при `savedInstanceState == null`; восстановленный фрагмент не заменяется.
- Возврат из настроек: `finish` с RESULT_OK и Activity Result API. Не очищать стек и не создавать Main через Start заново.
- Яркость/настройки применяются к существующему Main. Bitmap перезагружается только при смене стиля; смена языка вызывает однократное пересоздание Main.
- Справка в шапке Main открывает стартовую инструкцию. Кнопка «Старт» оттуда возвращает существующий Main с загруженными баннерами (`returnToExistingMain`). Системный Back на Start сохраняет предусмотренное эталоном завершение задачи.
- Онбординг после обновления/принудительного вызова сохраняет состояние при пересоздании. Версия считается просмотренной только после «Старт»; посещение FAQ не завершает онбординг.
- Splash: 2 секунды после получения фокуса окном. Потеря фокуса, пауза и уничтожение отменяют переход; возврат запускает новый интервал. Защита от двойного перехода. Ранний эксперимент с удалением задержки отменён.

## 6. Награды, реклама и диагностика

Общие правила:

- RewardAccess хранит право на текущую локальную дату. `last_stealth_activation_date` в ISO yyyy-MM-dd и `stealth_mode_enabled` записываются вместе. Повторное включение в те же сутки доступно после отключения.
- Только callback выдачи награды открывает доступ; закрытие/ошибка видео не являются наградой. RewardSession предотвращает повторную выдачу за один показ. Полученную в фоне награду сохранять сразу.
- Проверять истечение у ближайшей полуночи и не реже раза в минуту с учётом смены часов/часового пояса. В фоне отменять задачи, при возврате обновлять состояние.
- StealthRewardDialog показывает недоступность/загрузку/готовность/ошибку. Просмотр доступен только после загрузки; после ошибки — повтор guarded-загрузки. Поздний callback не открывает закрытый диалог заново.
- Обычные, accessibility- и программные нажатия переключателя обрабатываются согласованно; подавлять listener только при render, не фильтровать действия через isPressed.
- Состояния запросов, поколения callbacks, запрет дублирующих загрузок; освобождение SDK/View/listeners при уничтожении. Late callbacks не трогают уничтоженную Activity.
- Тяжёлые диагностические снимки ограничены DiagnosticThrottle: максимум раз в минуту, сбор вне главного потока. Частые тики обновляют лишь лёгкие метки. Обычный no-fill не превращать в искусственное исключение Crashlytics.

Применимые рекламные особенности эталона:

- Выбор региона: SIM, затем системная страна Resources.getSystem(), а не язык приложения/Locale.getDefault(). AdRegionPolicy покрыта тестами. Сохранить собственную региональную политику российской версии, если она отличается.
- AdMob: единая очередь первоначальных запросов, refresh и retry. Минимум 60 секунд после запроса/загрузки/показа, backoff ошибок 60/120/240/300 секунд, независимые top/bottom.
- BannerTimingRegistry сохраняет ограничения через пересоздание экрана/процесса; монотонное время и номер загрузки устройства в banner_timing, исключённом из backup. После перезагрузки с сохранёнными данными — защитная минута.
- Для ручного refresh AdMob в кабинете обоих блоков отключено автообновление. Это внешняя настройка, одним переносом Kotlin-кода её не изменить.
- У sticky-баннеров Яндекса обновлением управляет SDK. В эталоне ограничиваются первоначальные запросы; нельзя обещать общий минимум 60 секунд для внутренних обновлений SDK. Не добавлять параллельный refresh/retry; проверить возможности используемой версии SDK при переносе.
- UMP, если используется: privacy options приостанавливает очередь новых запросов, но не скрывает/не уничтожает загруженные баннеры. После закрытия читать публичный canRequestAds(): при разрешении оставить объявления, при запрете очистить. Недоступная форма не сбрасывает рекламу. Не сравнивать внутренние IAB preferences и не сбрасывать consent при каждом запуске.
- Баннеры должны сохраняться при возврате со Start и из privacy options: не ждать новую минуту из-за ненужного уничтожения уже загруженного объявления.
- Yandex rewarded: диагностировать этап load/show/request и ответ SDK, сбрасывать loading при синхронной ошибке, не загружать повторно готовое объявление и не запускать бесконечные повторы. Успешная загрузка demo не доказывает доступность рабочего блока в Германии/другом регионе. Причина исходного no-fill на физическом устройстве не установлена.

## 7. Зависимости, R8 и безопасность

Технический ориентир эталона, не требование слепо обновить российский проект: Kotlin 2.2.20, AGP 9.4.1, Gradle 9.6.0; minSdk 24, compileSdk/targetSdk 36, Java/Kotlin target 11 с desugaring. Фактические версии брать из gradle/libs.versions.toml и wrapper; совместимость SDK и среду сборки целевого проекта проверить отдельно.

- Упорядочены зависимости через каталог версий. Meta/InMobi приходят через адаптеры; Unity подключён отдельно по необходимости конкретного адаптера. Транзитивный Picasso не добавлен как собственный API приложения.
- Constraints фиксируют проверенные версии вспомогательных библиотек без лишних прямых зависимостей. Сравнивать итоговый dependency graph, не только каталог.
- Release: minifyEnabled и shrinkResources. Использовать consumer rules SDK; не дублировать широкие keep/dontwarn. Сохранять SourceFile/LineNumberTable для диагностики.
- Legacy drawable, выбираемые через getIdentifier, перечислены в res/raw/com_divinegames_mousemover_keep.xml. generated_* — логические ID, keep ресурсов для них не нужен.
- mapping.txt — результат R8 для конкретной сборки; его нельзя переносить вместо правил или использовать от другой APK. Не копировать app/release и сборочные результаты из эталона.
- Сохранить HTTPS/network security, проверить exported-компоненты, permissions и backup. Не переносить секреты, подписи, google-services.json другого приложения и производственные рекламные ID.
- В эталоне largeHeap=true осталось. Маленькая текстура сама по себе не доказывает возможность безболезненно убрать этот флаг.
